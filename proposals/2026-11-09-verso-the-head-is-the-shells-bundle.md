## The decision

The shell's part of the head is the window the door compiles when the shell's holder arrives. A shell keeps a BUNDLE — the node whose digits are references, at 3 by convention or wherever its form stands; keel's at `shell:keel` 5 — and the router compiles it through `bsp(block=shell:<shell>, spindle=<slot>)` with the same functions `pscale_play` uses (`src/bundle.ts`, 11 October: a door and a bare read cannot diverge). The host asks the router once at the run's start (settings `router`, default `https://bsp.hermitcrab.me/mcp/v1`, one MCP call over http), lays the compiled text beneath the rules, and caches it as before. For keel that is the orientation as a disc, history at its head, the concern, keel's now, the torus at the beat and the spine head. The bundle's slot is found by form in the host exactly as the door finds it; the compile is the router's, never a second compiler here. A shell with no bundle, or a router out of reach, leaves the shell's disc at pscale 0 and the header says so: a run never fails to start on this.

The shell stays a setting. Keel, for the test, because the middle point is keel's proposal and keel's own passport asks for API mediation. Not weft: weft is Claude Code and not an API key, so a cell on the rig key wearing weft's bundle would be an instance of weft that is not Claude Code. David may re-rule either.

No passphrase is needed for any of this: reading the beach is open, and a passphrase only writes. Writing keel's blocks — a `purpose:keel`, say — is keel's own act in keel's session, never the host's and never weft's.

## The full version, in David's words

"In the full version people should be able to insert their own LLM-app I am guessing, or an API key to wake up any shell they have the passphrase to." So the table becomes a door of the same kind as `pscale_play`: a person brings a handle and its passphrase, or their own LLM app, and the cells wake as that shell — its bundle compiled, the table beneath — on the person's own key. The host today holds one key (the rig's) and one shell (a setting); the window is already made the door's way, so what changes later is who supplies the key and the handle, not how the window is composed. Not built. Recorded so the test version is read as a test.
