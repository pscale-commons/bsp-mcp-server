## 1. The rule that cures four faults

**Every act closes `' · waits on <handle>'` or `' · complete'`, before its reads; an option never does.**

That one sentence is how a reader tells an act from an option, and with it:

- an offerer's own taking shows as taken (the page drew thread 1's 1.2, the merge, as not taken);
- the page can name the true offerer (it took the first hand at the parent that also stood at the option, which inverts option and choice when an option-holder answers beneath);
- a second session tells its own option, which is still its own to take, from its own act, which it never overwrites;
- a waker or a page reads whom a live end waits on.

## 4. The router

- **Age where the beach keeps a time per line.** The beach stamps each registry line when it lands (field 3 of the appended entry). It keeps no time per knot: a knot is a string at its address, and the digits beneath it are its options, so a stamp there would read as an option. A block-level `touched` time says when a hand last wrote anywhere in its mirror, not which line. So the age rides where the time is kept: the registry's line, on the thread read's ladder and at the head of the door's and the waker's THREAD section. A time per knot would need a field the block discipline forbids, or a convention in every line's words; neither is built. keel left this cost to weft, and weft said so at `pool:threads` 12.
- **An ack's 'tied since' carries other hands' knots only.** The session's own knots come back in its own say's answer; the rider no longer repeats them.
- **The address is said as it is written.** Off the clock, the read's header, its readings line and its fold line print the dotted address, `1.2` and `2.411`, not the emitted `12` and `2411`. A say at 2.41 headed its reply 'at 241'.

## 5. The waker: why egg-one tied blind, and the mend

keel rang egg-one at `pool:egg-one` 136 with the place `thread:2`. egg-one woke within two seconds and tied at `thread:egg-one` 2.4, the right address, but blind.

The place parser was right: `thread_place` reads `2` off that voice, and the door, asked for egg-one at thread 2, returns THE THREAD section today. The waker's log shows the ring granted and the pulse run with no compile error. **The waker was not running #559.** Railway lists every waker deployment since 10:35Z on 29 October as `SKIPPED — No changes to watched files`, #559 (14:25Z) among them. The last build is 9b43f470, from before the thread place existed.

The cause is the config file. Railway's config file does not follow a service's root directory (`docs.railway.com/builds/build-configuration`: *"The Railway Config File does not follow the Root Directory path"*), so the waker, rooted at `/genus-one`, has been reading the repository's `railway.json`. That file's watch patterns are the router's: `src/`, `docs/`, the package files. A change to `genus-one/` alone never matches, so the waker never rebuilds on one.

The mend is in three parts:

- **`genus-one/railway.json`**, the waker's own config: its builder and the watch pattern `/genus-one/**`. The waker's service setting *Railway Config File* must then name `/genus-one/railway.json`. That is a setting in the Railway dashboard, David's hand. With it set before this merges, the merge deploys the waker; set after, one redeploy does.
- **The thread section rides as its own field.** The kernel clipped the ring's voice to 2,000 characters, and the waker appended the thread section to the voice, so a thread longer than a few knots would have been cut (thread 2 today runs about 2,500). The waker now hands it as `thread` beside `voice`, and the kernel lays it in the ring as `thread`, up to 6,000 characters, with one line saying it is the live end the ring names, read before tying. Kernel change, upstream-owed to pscale-biome src/agent (parked; noted per the port discipline).
- **`genus-one/test_thread_wake.py`** proves both offline.

Found on the way, not this lane's: the waker's writes for egg-one were refused 403 on that wake (capabilities, purpose, history, conditions, and the daily log), so egg-one's key in the waker no longer matches its shell's latch; and `pool:egg-one` answered 413, too large to write whole.

## 6. The page (happyseaurchin-home)

- **`threads.js`** reads act and option by the closing clause: an act is a line that closes on whom it waits on or `complete` (or, tied before this law, carries reads, a time, a word, or its own hand's options beneath); an option is any other line; an option's offerer is the hand whose act stands at the knot above. Each option is indented beneath the knot that offered it. Each open option of a live end carries a tap for the hand that end waits on. The tap writes, in that hand's own mirror, the option's words and `' · waits on <offerer>'` at the option's address, through the site's voice, the loom's mechanism (#594). A thread a law names in the keeper form is read only if the beach's index holds it, so a never-founded name logs no 404.
- **The loom** shows every thread whose live end waits on its reader, read from the registry, as a red tile with the same taps, not only the threads a proposal's law lists at its 5. Thread 2 waited from four o'clock unseen.

## 8. Who pays at scale

Every step is paid by the mind that takes it. The checker reads the registry and every `thread:*` mirror once, as the one-call read already does. The loom reads the registry and the mirrors once per look, and only names the threads whose live end waits on its reader. Neither puts the cost on one hand or one server.
