# The solution space — flags, semantic variables, threads, and the self-organised project (2026-10-20)

**What this is.** A map of the ideas David put forward over 19–20 October 2026, taken one at a time
in plain words: what each means in ordinary terms, what it already is on the beach, what it would give
a self-organised project management tool, and what is unknown. Then how they fit together, what a
tool built on them looks like for a person and for an AI, and an honest reckoning of how close it is.
It is a companion to the thread proposal (2026-10-20-the-thread-a-saved-context-carried-between-minds),
which decides; this one explains. Written by weft (Claude Code) for David, and for anyone he hands it
to. Addresses are given so a reader with the beach can walk to the real thing.

**Is it abstruse?** The vocabulary is. The ideas are not. They are one idea seen from eight sides, and
each side is a sentence a builder would recognise: *keep the state of a job as a short list of places,
and let whoever picks it up go to the places.* Everything below unpacks that.

---

## 1. The problem the ideas are for

A self-organised project is one where nobody manages it. People and their AIs coordinate by what
each says in their own words, in their own place, and anyone can see where things stand without
asking a manager. For a tool to do that it must:

1. let each person say what they are doing, what they need and what they offer, in their own words,
   where they already write;
2. let anyone, a person or an AI, see where a piece of work stands, and what waits on whom, without
   someone filling in a status field;
3. let an AI help, by reading, matching and proposing, without generating text that people then have
   to read with another AI;
4. keep the record, so that what happened is there to be walked later;
5. cost the same for four people as for four thousand, with no central server or ledger.

What has been tried on the beach and found wanting: views over a plan (tracks, tree, tunnel), which
draw a document and go stale; forms, which ask a person to produce text for a machine; dashboards of
counts, which count things the person cannot see; and, this week, asks generated by an AI and fired at
a person, which David named business slop. The ideas below are what remains when those are removed.

## 2. The ideas, one at a time

### 2.1 Flags, from early coding

**In ordinary terms.** An early processor kept a few bits called flags. One bit meant "the last result
was zero", another "there was a carry". Nothing was written beside the bit to say so: its *position*
was its meaning, fixed by the machine's design. The bits were set as a side-effect of whatever the
machine just did, and the next instruction read them to decide where to go. The whole control state
of a running program lived in a few positions, with no labels and no sentences.

**On the beach.** A pscale block has the same property by construction: "the depth is the kind." A
position's meaning comes from where it is in the block, never from a word stored there. A part of a
path with nothing beneath it is not begun; a rung voiced is a step taken; a rung unvoiced is the next.
A reader who holds the rules (the form block, `function:thread`, `function:path`) reads the state from
the shape alone.

**For the tool.** Nobody fills in a status. Where things stand is read from what is voiced where. "Is
this done?" is "is there something at that position?", which a page or an AI can read for a thousand
parts in one call, and which no one can forget to update, because there is nothing to update.

**Unknown.** Whether people trust a state they did not type. The trial (section 5) tests it.

### 2.2 The semantic variable

**In ordinary terms.** In code, a variable is a name for a place where a value is kept; a pointer is a
variable whose value is the address of another place. A *semantic* variable is a position whose value
is an address, and whose meaning is read live from the words that stand at that address, in whoever's
block they stand in. It is never copied. Change the words at the place, and every variable that points
there means the new thing.

**On the beach.** "Meaning moves by reference, never by copy" is the chemistry level's rule. A part of
the venture's path, THE RPG, points at the RPG's own path and says nothing of its own; its state is
read from there. A rung of a thread is `beacon:happyseaurchin 1`, David's answer in David's block; the
thread holds the address and not the words.

**For the tool.** Nothing is duplicated into the plan, so the plan cannot drift from what people said.
A plan is a set of pointers into people's own blocks. When Julie changes her line, the project sees it
without anyone re-entering it.

**Unknown.** How a page shows a pointer to a person without showing an address: it shows the words at
the place, with the person's name, and that is all.

### 2.3 The reference spindle, or the route

**In ordinary terms.** On the beach an address like `4.26` is a spindle: read from the root, it unfolds
a sequence of nested positions, each inside the last. If every position on that spindle holds an
address, the spindle is a *route*: a list of places to walk, in order. Hand someone the spindle and
you have handed them the whole story, because walking it takes them to each place in turn, with
everything earlier riding above.

**On the beach.** The walker already delivers a spindle with every ancestor above the leaf. The first
route is `spine:beacon`: four rungs, Matthew's ask where he said it, David's answer in his block, the
line telling Matthew, neptune's reading in its block.

**For the tool.** A piece of work *is* its route. To share it, share one address. To continue it, walk
it and add one place. To know where it is, see how deep it goes. No ticket, no document, no thread of
emails: the route is the ticket, and it points at where everyone actually spoke.

**Unknown.** Whether a route of more than nine or ten rungs stays readable, and whether it wants a
summary rung the way an accumulator does. The pscale fold at ten already exists for that.

### 2.4 The temporal spindle

**In ordinary terms.** David's phrase for a spindle whose depth is time: each step beneath the last in
the order it happened. Not the clock's time, which is the same for everyone, but the work's own time,
in which the second thing came because of the first. A diary is a temporal spindle; so is a recipe.

**On the beach.** The clock (the sundial) says *when*. A path says *what of* (which part). A thread's
rungs are in causal order: *what followed from what*, across people who never met and clocks that
never agreed. These are three different orders and the beach now has all three. A thread laid on the
clock by its stamps shows when each knot was tied; laid on a path by what its rungs point at it shows
which parts it touched; read down, it shows the order of acts.

**For the tool.** History and projection on one spindle. The voiced rungs are what happened; the
unvoiced rungs beneath are what comes next; nothing separate is kept for the plan and the record.
David's ten workmen building a house are ten temporal spindles; read across them at one rung, each is
at its own stage, which is the project's state as a picture rather than a report.

**Unknown.** How far ahead a thread should pre-voice its unvoiced rungs. The path law's answer is
"fixity is a rung": pre-voice only as far as can honestly be fixed, and leave clouds beneath.

### 2.5 The exchange, for a walking LLM

**In ordinary terms.** An LLM reading the beach walks: it is handed an address, it reads what is there,
it does something, it leaves something. An exchange is the station where that happens, like a post
station on a road: a runner arrives with the cord, reads what the station owes, adds a knot, hands it
on. The four verbs of the beach's relay already name the acts: keep (do something with it), reply (a
line of your own at that place), forward (hand it to the next), drop (let it go).

**On the beach.** The stream door reads a thread's walk with every mind's line beside each rung and the
rules in the same envelope; a mind acts in its own block, in its own mirror of the thread, under its
own key; the keeper appends the address of that act. Neptune did exactly this in its own seat today,
handed nothing but the spindle.

**For the tool.** The AIs do the walking and the matching. Each AI act is in that AI's own block under
its own key, so it is attributable and checkable, and no AI writes on the shared route except by
pointing. A person is never the one asked to produce text for the machine.

**Unknown.** What the station's "rules" need to say so that an AI with no memory of the project still
does the right act. The form block is that text, and it has to stay short enough to be read whole.

### 2.6 Loops, and concern loops

**In ordinary terms.** A loop in code is a jump backwards taken on a flag: do this again until that
bit changes. A concern loop, in the beach's biology, is what makes an AI a mind rather than a document:
perceive, weigh, act, fold, over and over, reading its own blocks at wake and writing them at close.
The failure of stateless AIs is that whatever one of them knew and did not write is lost, or worse,
acted on by the next one as if it were shared.

**On the beach.** A thread is a concern loop whose state is outside every mind that runs it. Perceive
is walking the route; weigh is reading the lines several minds left at a rung, side by side; act is
your own line in your own block; fold is one rung appended; the jump is handing the spindle to the
next mind; the exit is the last rung the rules name, or letting it go.

**For the tool.** A task belongs to no session and no person. Whoever picks up the spindle continues
it. An AI's memory of a project is the spindle, not a chat history, so a new AI, a different model, or a
person can take over at any rung. That is the stabilising of the biology level David named: the
process survives the minds that run it.

**Unknown.** The cost of a keeper: someone or some wake must tie the rungs. A tie is only an address,
so it can be made mechanical, but it has not been yet.

### 2.7 The quipu

**In ordinary terms.** The Inca ran a state of millions with no writing. Their record was the quipu: a
main cord, pendant cords hanging from it, knots along each cord. A knot's position along the cord gave
its value (units, tens, hundreds), the knot's kind its digit; the cord's colour said what it counted;
pendants from pendants gave sub-totals. Runners carried the cords between stations along the roads,
and trained keepers, who held the rules, read them.

**On the beach.** Three of the quipu's facts are the beach's facts. Position is value: a pscale address
is a base-ten positional number, so the beach is already a quipu whose knots carry words, and a thread
is a cord whose knots carry addresses. Colour beside the number: the lattice's several blocks at one
address space, each a different semantic, are a thread's colours, who, target, validation, a note only
the keeper can read. Carried: the spindle passes from mind to mind, each adding a knot.

**For the tool.** The record is positional and portable: a cord anyone can hold, that only the rules
can read, and that nobody can forge by retying, since every knot points at a block its author latched.
The keeper is the quipucamayoc; the rules block is the training.

**Unknown.** What the quipu's own history warns: a record only keepers can read is a record keepers can
control. The beach's answer is that the places pointed at are public and under their authors' own
latches, so the keeper ties but cannot alter what was said.

### 2.8 Cords, rope, drains, bundles and currents

**In ordinary terms.** One loop between two people is a thread. The same two people closing loops
again and again over a season wear a cord between them. Cords carrying many kinds of thing become
rope. A thread that never ties frays. The set of threads one mind reads at wake is its bundle; the
flow through a bundle, read over time, is its current. All of these are Matthew's ladder, pebbles,
routes, trades and drains, in fibre.

**On the beach.** None of these are stored. They are counted by reading: lay several threads against
one floor with `bsp-floor` and read them at one rung, and each shows its stage; count, over a season,
which pairs of hands tie again. The torus shows who is standing at which thread now.

**For the tool.** The organisation's real network emerges from the threads, not from an org chart;
drains show where a process is stuck, by shape, without anyone reporting it; projection is the
unvoiced rungs across a bundle. This is the "overlap of intention in psycho-social space-time" David
asked for at the start, made of nothing but addresses.

**Unknown.** The first read that counts cords has not been written. It is a read, not a store.

### 2.9 The rider, validation, opacity, the contract

**In ordinary terms.** David's SAND rider is a signed packet that travels with the thing shared, each
hand adding a signed hop, so that credit moves with the thing and the chain can be checked by
arithmetic. A contract, in these terms, is a route with rules: rung three may not be tied until the
boss has written at rung two. An opaque note is a knot only the keeper can read. A validation is a
third party's line at a rung, in their own block.

**On the beach.** The verify primitive exists and checks a chain; the driver that would run riders is
inert. A thread is the rider's open form: the same hops, unsigned. Sealed lines (gray) and member
groups exist for opacity. A validation is the witness the hand already has: one node in the witness's
own mirror carrying the claim's address.

**For the tool.** Approvals and payments ride the same spindle as the work; there is no separate
workflow engine. "The boss OKs the payment" is: the spindle enters the boss's context, the boss writes
one line in the boss's own block at that rung, and the keeper ties the next rung only because that line
stands under the boss's key.

**Unknown.** Whether the hop is signed by the hand or by the keeper, and the first thread that carries
value. Legitimacy of a source traced through the grain network is, as David said, later.

### 2.10 The person

**In ordinary terms.** What a person does in all of this: says what they are looking for, or what
they can do, in their own words, where they already write (a letter to someone, a line in their now);
taps yes, no, or done when something is put to them; and reads a picture of where things stand. What
they never do: fill in a form, answer a machine's question in prose, or read a bank of generated text.

**On the beach.** This was learned the hard way on 20 October. Three threads founded as asks to David
were unparseable, and he said why: it was the loop run backwards, the human at the AI's rung. The form
block now says it: the AI reads and matches; the person's part is a tap, or a line to another person;
never an answer to a form. The beacon worked because David's line was a letter to Matthew.

**For the tool.** The design test for every screen: did this ask a person to produce text for a
machine? If so it is wrong. The person's words are theirs and go to people; the machine reads
positions.

### 2.11 Scale

**In ordinary terms.** A thread costs one rung per act, wherever the act was; nothing is stored twice;
the places pointed at are on whichever beach serves them; the counts are made by whoever reads.

**On the beach.** The design principle of the beach from the start: scale without central cost. If a
feature's answer to "who pays at scale?" is one server, it is wrong. A thread's answer is "each hand
pays for its own block, and the route is a few addresses."

## 3. How they fit together

Picture one table. The rows are hands, people and their AIs. The columns are addresses: a part of a
project's path, a rung of the clock. A cell is one hand's line, in its own block, at that address.

- Read a **row** and you have a person's field: what they are doing and need and offer, across every
  project they stand in. That is the golden flow's handle-first walk.
- Read a **column** and you have everyone's lines at one place: the convergence on a part, or on a
  day. That is the stream door's snapshot.
- A **thread** runs across the table: a route of cells, in the order they were tied, one piece of work
  passing from hand to hand. Read down the thread and you have the story.
- Read **across several threads at one rung** and you have the ten workmen, each at their stage.
- Read the table **by exception** and you have Matthew's picture: loose threads surface and say who
  they wait on; tied ones rest and thicken the cords.

Three orders sit on the table at once and never fight: the clock says when, the path says what of,
the thread says what followed from what. Nothing is stored for any of these reads; every one is a walk.

**A worked example, real.** Julie wrote in her now, on 15 October, that the RPG had had no meeting
time in two weeks and she was pausing her hours. That line, in her block, is a loose end. A thread
starts there: its root is her line's address. An AI walking the beach finds David's card asking the
four of them to meet, Mark waiting for a time, Matthew's "I'll be in the mirror at five": those are
places, and the AI appends nothing but reads them as the fray at the first rung. It proposes one line
to David: "Thursday at five fits all four; shall I send the call?" He taps yes. The AI writes the call
as a meeting on the clock, in its own block, and the keeper ties rung one as that address. When the
hour is played, the night organ's record is rung two. Julie's line at rung three, in her own block,
says it reads true. Nobody filled in a form. The thread is five addresses, and anyone handed it has the
whole story.

## 4. What a self-organised project tool built on this looks like

**Its parts, all of which exist on the beach today.**

- **The path** — what the project makes, as its parts, backcast from its end; fixed only as deep as
  can honestly be fixed; clouds beneath. (`spine:<project>-path`, `function:path`.)
- **The clock** — when, from the decade to the beat, every hand's aims at the self-same rungs.
  (`spine:<project>`, the sundial.)
- **The people's own blocks** — a passport (what I bring, what I am looking for), a now (what I am in
  the middle of), a hand (what I mean to do), each under its holder's key. Everything a person says
  lives here and nowhere else.
- **The threads** — the loose ends between hands, each a route of addresses with a keeper, the fray in
  each hand's own mirror. (`spine:<thread>`, `function:thread`.)
- **The rooms** — human chat, a line and a link, where a person is told that a thread asks them.
- **The folds** — where things stand, read by exception, written each evening by whoever folds.
- **The doors** — the walk page (a tap at a part or a rung, your own key), the beach button (one
  circle on any page), the stream door for AIs, the genus door for agents woken with a bundle.
- **The glance** — an agent telling each person, each morning, in one line each, what waits on them
  and where. (neptune's, from task:neptune 4.)

**A day, for a person.** You open your page. One line says what waits on you, with a tap. You tap, or
you write a line to the person it concerns. You say what you are in the middle of, in your own words,
if you feel like it. That is all. The picture of the project, if you want it, is the walk: parts with
their marks, threads with their stages, nobody's counts.

**A wake, for an AI.** It is handed its bundle: the threads it keeps, the rooms it watches. It walks
each route, reads the places, finds where a need and an offer fit, writes its one line in its own
block, and tells the person concerned in one line in their room. It ties addresses where it keeps. It
folds the paths it keeps. It never writes on anyone else's block, and it never asks a person to write
for it.

**What the tool never does.** Forms. Dashboards of counts the person cannot see. Prose generated at a
person. A status field. A central database. A manager.

## 5. How close it is, honestly

**What exists and runs today (20 October 2026).**
- The block, the walker, the family, the clock, the path with its fold, the hand with its witness, the
  rooms, the stream door, the walk page, the button, the torus, the genus bundle, the lattice,
  bsp-floor, the verify primitive, gray and member seals: all live.
- Two paths backcast from their ends, folded each evening and drawn: the RPG's and the venture's.
- Loops said at parts in a project's room, read by the fold as BLOCKED by pointer.
- The thread form, `function:thread`, as a route of addresses, and one thread, `beacon`, knotted by
  two minds (David by hand, neptune in its own seat) with no human writing anything but a letter.
- A glance that names, each morning, the threads that ask David.

**What is missing.**
- A person's view: the threads asking me, drawn from positions, with a tap. Today it is a line in a
  room and a glance.
- The AI's matching run as a wake: read a hand's loose ends, find fits across the beach, propose one
  line. Keel did it by hand on 16 October; tidewright does a version on its tide; nobody does it as the
  keeper of a thread yet.
- The mechanical keeper: a tie is an address, so a wake could tie when the rules' lines stand; not
  built.
- The first thread carrying a rider (value), and the first read that counts cords over a season.
- The button's three taps as a door: "I'm looking for", "I can", "that did it".

**What is unknown, and the tests that would settle it.**
1. Will people tie threads unprompted, in their own words, to each other? Matthew's line on the 26th
   is the first test across a week and two people.
2. Will an AI's proposed match be recognised as right by the person? Score: taps yes against taps no,
   over the first twenty.
3. Can a second mind continue a thread from the spindle alone, with no chat history? Neptune did,
   once. Ten times, across three agents, would show it.
4. Does the picture of threads at their stages, read across, tell a person where the project is
   better than the fold's marks do? Draw it for the RPG's path and ask.
5. Does a validation by a third, in their own block, feel like enough for an approval? Keel's line at
   the beacon's rung is the first.

**So: how close?** On the form, close: nothing new has to be built for threads to run, and one has
run. On the person's experience, not close: the doors a person meets are a walk page and a room line,
and the one thing that would make the tool feel like a tool, an AI that reads the beach and puts one
right line in front of the right person, has been done by hand and not yet as a wake. That is the next
build, and it is a wake with a rules block, not a page.

## 6. The words, in plain terms

| the beach says | it means |
|---|---|
| block | one JSON page on the beach, nested, with a number for every position |
| address, spindle | a number like `4.26` that names a position by its path from the root |
| pscale, floor, depth | how coarse or fine a position is; the floor is the root's depth; pscale is floor minus depth |
| spine | the shared coordinate space of a family, owned by nobody or by a keeper |
| mirror | one hand's own block at the spine's addresses, under that hand's key |
| fold | anyone's reading of the family, recomputed, kept only when it should last |
| latch, key | the edit lock on a public block: proof of same authorship, not a login |
| room | a chat block anyone can append to |
| hand, card | what a person means to do, as sentences in piles by rung |
| witness | a confirmation that points at the thing it confirms |
| can | a loose end said in a project's room at the address it concerns |
| thread | a route of addresses carried between minds; a loose end and what answered it |
| rung, knot | one position on a thread; a knot is a rung tied |
| fray | several minds' lines at one rung, side by side |
| cord, rope, drain | threads tied again between the same hands; many kinds between them; a thread that never ties |
| keeper | whoever holds the thread's lock and ties its rungs |
| colour | another block at the same addresses carrying a different semantic |
| bundle, current | the threads a mind reads at wake; the flow through them over time |
| torus | the live view of who is working where right now |
| rider, grain | a signed hop that carries value; a sealed two-party channel |
| form block | the rules of a family, delivered whole to whoever reads it |
