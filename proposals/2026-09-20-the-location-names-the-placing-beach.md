# The Location names the placing beach, not the table (2026-09-20)

**Status**: RULED and APPLIED. David, 2026-09-20: "proposal and canon fix". The canon
write is done, the standing text archived first; this file is the record the law write
owed (`2026-08-05-law-writes-get-their-record.md`). Found while repairing David and
Julie's table after the mirror could not find their characters.

## 1. The fault

`char-creation` branch 2, the ceremony every character at a brackenfoot table is written
by, said this of the passport's position 3:

> the appearance sentence, then ' Location: `*:<this-table-url>:spatial:brackenfoot:211`'
> (the Slip, digit-path copied plain, never dotted — and the beach is THIS table, never
> the spine).

The Author walk (`lighthouse:2` at the canon) founds a table as a REFERENCE table by
default — world-genome 1.54 — and says in the same breath: "**NO spatial and NO identity
copies**: a Character cannot write to what its table never holds, and a re-authored canon
reaches every table at its next engage." The place is read live from the canon through the
table's own `keeper:scene` position 3, its PLACING star-ref.

So the ceremony told the author to point the Location at a block the table is forbidden to
hold. Every character made at a reference table points at nothing.

Live evidence, all three characters standing today:

| character | table | Location as written |
|---|---|---|
| garth | `/w/brackenfoot-david-julie` | `*:…/w/brackenfoot-david-julie:spatial:brackenfoot:130` |
| equinox | `/w/brackenfoot-david-julie` | same, and that table holds no `spatial:brackenfoot` |
| Ugarth | `/w/brackenfoot-open` | `*:…/w/brackenfoot-open:spatial:brackenfoot:120` |

Both tables' `keeper:scene` carry the correct placing into the canon; only the passports
were wrong.

## 2. Why it survived a week of play

- **A move never rewrites the origin.** The character page and the group page both match
  `LOCATION_RE` and replace only the digits, so whatever origin genesis wrote persists
  through every walk.
- **The table's own doors fall back.** The group page resolves a place through the keeper's
  placing when the passport's ref misses, so play kept naming The Village and The Long
  House correctly and nothing looked broken from inside.
- It shows only from outside: a door that follows the passport — the mirror, an LLM asked
  where a character stands — finds no block and reports nothing.

The instruction was right for the other founding shape. `lighthouse:2.1` keeps a full-copy
FREEZE for a run that must not move, and there the table does hold the spatial. The
sentence was written for the freeze and never revisited when reference became the default.

## 3. The law as it now stands

Rewritten at `char-creation:2`, canon (`/w/brackenfoot`), and in the open table's verbatim
copy:

> ' Location: `*:<the placing beach>:spatial:brackenfoot:211`' … THE PLACING BEACH IS THE
> ONE THIS TABLE'S `keeper:scene` NAMES AT ITS POSITION 3, and it is usually not this
> table: a reference table — the default of the Author walk — holds no place of its own and
> reads the canon's live, so the Location points at the canon spine; only where the Author
> froze a full copy here does it point at this table. The character's blocks are still
> WRITTEN here; the Location only POINTS, and it must point where the place actually
> stands, or every door that follows it finds nothing there.

The distinction the old text blurred: **write at the table, point at the placing.** Both
halves of "never at the spine" are kept — no character block is ever written to canon.

## 4. What was done

- `archive:char-creation:2026-09-20` at the canon holds the standing text, read back
  identical, before the replacement.
- `char-creation:2` rewritten at `/w/brackenfoot` (the cartridge GM lock) and at
  `/w/brackenfoot-open` (weft's operational lock), which held a verbatim copy.
- The three standing passports repaired to the canon spine: garth and equinox at 130 (The
  Long House, verified to resolve), Ugarth at 120.

## 5. Left standing, deliberately

- **`/w/brackenfoot-david-julie` still holds the old copy of the ceremony.** That table's
  kit answers to its founder's lock, which is not held here. Its two characters are already
  correct, so only a character made there later would inherit the old sentence.
- **Astrel at `/w/brackenfoot-open` still points at its table.** Its key was not given.
- **A kit copy is a lockfile.** A re-authored canon reaches new forks only; every existing
  table keeps the sentence it was minted with. That is the design (the run's rules must not
  shift underneath it), and it means a fault in the ceremony has to be swept per table.
  Worth a thought at the next founding: which parts of the kit are law that should track
  canon, and which are the run's own.
